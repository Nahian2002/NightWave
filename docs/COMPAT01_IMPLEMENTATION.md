## Implementation and preserved boundaries

The initial API23 lint audit found six NewApi errors: two Configuration/LocaleList calls each in strings and typography, URLConnection.contentLengthLong in legacy artwork, and ApplicationInfo.minSdkVersion in updater verification. Locale access now uses ConfigurationCompat; thumbnail size reads the existing Content-Length header as Long. The updater guards per-source install settings at API26 and uses Android's installer handoff on older Android, preserving explicit OS approval.

Signed feed metadata has an additive optional `minSdk` field. The offline publisher derives it from the actual verified APK using aapt, never user-entered release text. API23 requires that authenticated field (missing metadata fails closed); API24+ still checks the actual archive minimum and rejects disagreement when metadata is supplied. Existing modern clients ignore the extra field; newer clients continue to accept legacy metadata on API24+ with archive validation. Library, backup, widget, preferences and installed-data schemas are unchanged. Disabled feed/public key remain unchanged; no feed activation or public artifact is performed.

APK signature verification now follows each archive's actual declared minimum rather than forcing API26 for both new and historical APKs. The candidate gate explicitly requires reviewed minSdk23; prior code39 is independently compared by its own declared minimum, preserving signer continuity without pretending it could run on API23. This allows the platform verifier to demand the signing schemes needed by Android6. Modern compile/target36, pinned dependencies and NIO desugaring remain unchanged. Two JVM regressions cover missing/incompatible signed minimum on API23 and actual/signed disagreement plus legacy-feed support on modern Android.
