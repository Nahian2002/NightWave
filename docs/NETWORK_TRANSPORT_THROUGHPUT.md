## Deliberate transport changes

- Playback uses the Media3 OkHttp adapter, pinned at 1.6.1 to match the existing Media3 family, instead of the platform HTTP factory. It negotiates HTTP/2 when supported and retains HTTP/1.1 fallback. The playback client is reusable, separate from extractor metadata and authenticated Drive clients, with no cookies, disk media cache, whole-song URL persistence or fixed Wi-Fi/mobile binding. Existing user agent and 20-second connect/idle-read bounds remain. DefaultDataSource still owns local file routing, and existing HttpDataSource error/recovery handling remains.
- The existing guarded public-download client moves into a companion object so successive workers can reuse a pool. Individual cancellation still cancels only that transfer's Call. DNS/private/reserved-address rejection is textually identical apart from indentation; explicit per-hop redirects, source eligibility, byte/storage limits and audio/hash/import checks remain. No automatic redirect or credential policy is relaxed.
- Playback read-ahead may reach 120s instead of the pinned 50s default, with a 16 MiB allocation target and size prioritized over time. This is a buffer target, not a whole-process RAM ceiling. Minimum buffer stays 50s; startup/rebuffer thresholds match the actual pinned Media3 defaults of 1s/2s. An initial build used more conservative thresholds; it was superseded after verifying the cached 1.6.1 constants and is not the delivered candidate. Increased read-ahead can use more transient memory/data and must be checked on device, especially live/muxed fallbacks.
- Small network or document-provider reads accumulate in a 256 KiB buffered output rather than causing one file write per small read. The buffer flushes before the existing fd.sync and before any verification/rename/index commit. On exceptions the uncommitted tail is not flushed; existing private staging cleanup remains. Sequential local copy/hash blocks also use 256 KiB. No per-chunk fsync, whole-song memory allocation or artificial sleep/rate limit is introduced.

Audio/bitrate/source selection, original URLs/metadata, streams/manifests/fallbacks, queue/transport controls, consent, accounts, local import formats, all themes/features and data schemas remain. No source substitution, bitrate reduction, proxy, new authentication, private content access or provider bypass is introduced. A fast connection cannot force a remote server to deliver at line rate, and playback should stop fetching when its bounded buffer is full.
