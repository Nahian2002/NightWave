## Before and after

Owned-file import already copied into private storage, enforced size/capacity, synchronized index changes, deduplicated by bytes and committed the index last. It did not probe an actual audio track/sample before accepting a supported extension. The empty Library also spent its viewport on search, sort, playback, availability and paging controls before any files existed. Import completion refreshed only the Activity that started it, so a recreated screen could miss a completed import.

The existing system multiple-document picker remains. Each bounded batch now reports Copying, Checking audio and Saving. Android MediaExtractor must find an audio track and a positive readable sample before rename/index commit. A spoofed extension or empty container cannot count as imported audio. The checker always releases the extractor; import failure retains the original and existing library while removing only its own uncommitted temporary/final copy through the existing cleanup. The 100-file batch limit is explicit; partial successes, failures and unattempted selections have distinct counts. Successful imports reset search/filter/page so the new music is discoverable. Completion text lives separately from ordinary health/search messages.

User-owned supported MP4/WebM/3GP containers with actual audio remain supported, including audio in a video container. Existing direct-download audio-only validation stays unchanged. The supported extensions, 250 MB file limit, 5,000-song/32 GiB capacity, headroom, duplicate identity/lyrics references, stream handling, cloud imports, consent, provider capabilities and index schema remain. This check establishes a readable audio track/sample, not a full decode, every-frame integrity, codec guarantee, actual audible playback or seek test.

## Empty versus unavailable

Only a readable index with zero entries gets compact onboarding: import guidance, the full format/size list and the existing Import files action. Unused search/sort/play/filter/page/recheck controls are hidden only in that true empty state and return when entries exist. Downloads, extra sources, private Drive and the shared navigation/player shell remain. Search/filter no-results and an unreadable index cannot masquerade as a new empty library. An unreadable index still shows its preservation/recovery message and recheck path; it is never rewritten or treated as mass deletion.

The metadata-only availability filter is labeled Available, with an explicit size-checked accessibility label. File presence/size is not presented as a fresh media verification. A new Check audio option runs the same read-only track/sample probe off the UI thread; its result has separate wording. Failures overlay the cached display as unreadable, exclude that ID from this screen's playable set and expose existing recovery/import guidance without deleting or altering index/files. A failed check can be explicitly retried. Probe results are session-local and are not a persistent integrity certificate; later file changes and real device playback still require validation.

## Source choice and lifecycle

The existing searched-track save/permission action and Other audio sources remain. The latter offers explicit Import owned audio, supported catalog, authorized direct HTTPS link and Offline Library choices. Choosing Import opens the existing Library/picker once; Activity recreation does not relaunch it. Catalog/license guidance and all save/provider restrictions remain. No feature, provider, account scope or bypass is added or removed.

A lifecycle-bound listener observes the existing offline index key and schedules a fresh background snapshot, including when an earlier screen instance finishes an import. Changes during an in-flight health scan request a replacement read instead of publishing the stale scan. Listeners are removed when stopped. No polling, new index/storage schema, automatic repair or main-thread audio probe is introduced.

Existing file-import tests now use real WAVs instead of arbitrary bytes and an isolated context; these fixtures do not touch the installed library. Android cases are compilation only until actually run.
